## New findings (2026-10-05 pass)

### F-1 · Release signing silently falls back to the debug keystore
`app/build.gradle.kts` — the `release` signingConfig reads
`RELEASE_STORE_FILE/PASSWORD/ALIAS/KEY_PASSWORD` from gradle properties and
defaults to `app/debug.keystore` + `"android"` + `debug`. If you ever cut a
release without those properties set, you'll ship an `android`-signed build.
For personal use this is fine; before any distribution, fail the build when
they're missing rather than silently using the debug key.

### F-2 · FTS5 tables are write-maintained but never queried
`BibleDao.searchVerses*` all use `LIKE` (documented, verified why:
framework SQLite ships without the FTS5 module). But the app still creates,
indexes, and maintains `verses_fts_*` for all 10 translations in the runtime
database and rebuilds them on every v12→v13 migration. That's dead storage in
every installed DB (part of the 142MB prepop size) and dead trigger work on
every verse insert. Either wire real FTS5 (bundled SQLite) or stop
maintaining the runtime tables — keep the asset DB's copy harmless.

### F-3 · Migration doc-comment drift (cosmetic but real)
In `OpenBibleDatabase.kt` the comment block attributing "Version 5 → 6" sits
above `MIGRATION_6_7` (which is actually version 6→7), and `MIGRATION_5_6`
itself is defined at the bottom. `addMigrations` wiring and behavior are
correct; only the comments lie about which block is which.

### F-4 · `initialNavConsumed` is session-scoped, not route-scoped
`BibleViewModel.initialNavConsumed` is a plain `var` reset only by process
death. Navigating to a new chapter route does not reset it, so the "default
translation follows settings" behavior stays suppressed for the rest of the
session after any explicit route. This matches the stated intent (explicit
navigation wins); flagging because a fresh `bible/{t}/{b}/{c}` route reuses
the same ViewModel only in-process — behavior is correct but fragile to a
future NavGraph refactor that keys VMs per route.

### F-5 · `BibleViewModel.currentBook` uses `getBook(bookId)` unconstrained
`getBook` filters only on `id`; with the v10 composite PK
`(translationId, id)`, a plain `WHERE id = :bookId` returns whichever
translation's row SQLite picks (usually kjv). Correct metadata is
translation-independent, so it happens to work — but once a translation
differs in a book name (e.g. a localized edition), the top bar would render
the wrong name. Constrain by translationId.

### F-6 · TTS mid-verse speed change loses the current word's position
`TtsController.setSpeed` restarts playback from `resumeIndex` (the current
**verse**, not the current spoken position). Changing speed mid-sentence
jumps back to the verse start. Minor; document or keep.

### F-7 · Daily-verse alarm isn't rescheduled on settings change of enabled=false→time
`setDailyVerseEnabled(false)` stops the alarm only via `DailyVerseScheduler.cancel`
when the Settings screen calls it — if that path is ever skipped (widget,
BootRecovery) the scheduler still fires but `showDailyVerse` early-returns on
`enabled`. Safe by defense-in-depth; just noting the double gate.

### F-8 · Prepop DB copy on IO is still 200MB, gates every cold start
Verified: `StartupSplash` shows until `databaseReady`; on slow eMMC this is
seconds. A `LazyColumn`-friendly split (copy only `verses`/`strong_numbers`,
defer FTS/location tables) would cut cold-start. Not urgent.
